# Release candidate limitations

- **Enforcement boundary:** supported gateway-routed tools only. Unrelated OS, filesystem, browser, shell/network and intentionally unguarded connections are not intercepted. No universal Codex/Cursor protection.
- **MCP scope:** official SDK initialization/ping/tools discovery/calls, local stdio → existing JSON HTTP. No arbitrary upstream server proxy, remote OAuth, prompts/resources/sampling or universal client compatibility claim.
- **Operator trust:** loopback transport + administrator cookie/CSRF is a local OS-operator boundary, not independent production/multi-user authentication. A hostile local OS user/host compromise is outside this MVP isolation model. No public deployment.
- **Model proof:** genuine provider inference remains unverified and was not run. Scripts choose deterministic actions; real local tool execution is not model inference. SDK mocks/external receipts cannot assert verified-provider provenance. Paid experiments require fresh explicit opt-in and application budgets are not guaranteed billing ceilings.
- **Detection interpretation:** explainable policies/statistical rules, not validated ML threat probabilities. Novelty, denials and decoy contact do not independently establish malicious intent or confirmed compromise. Controlled local runs do not measure real-world model robustness or adoption.
- **Memory and forensic origin:** local HMAC/key signs content and provenance. It does not survive signing-key/host compromise, prove an honest source, or provide external attestation. Hashes alone establish consistency relative to a manifest, not trustworthy origin.
- **Uncertain delivery:** timeout/disconnect/cancellation after dispatch can leave a legitimately authorized effect committed. No rollback guarantee. Preserve exact request UUID/input; no automatic mutation retry or unguarded fallback. Exact replay rechecks current authority and does not re-execute.
- **Exports:** interrupted downloads fail without a falsely successful output; interrupted filesystem writes can leave a private partial file that must fail verification. Existing evidence files are never overwritten. An output is usable only after verification passes.
- **Persistence/capacity:** single local process/SQLite serialized mutations, bounded records/catalog, single-flight SDK/proxy and finite export sizes. No distributed/high-availability guarantees. Registration/historical active sessions are not proof of continuous connectivity.
- **Visual QA:** intentionally not attempted because saved browser access remains unresolved. DOM tests and HTTP data checks are not screenshots or desktop/mobile sign-off. Presentation timings are scripts, not measured visual walkthroughs.
- **Platforms:** the clean install/full suite/production server are verified under Node 24.10/npm 11.19; minimum Node 22.12 is declared, not a full independently verified OS/version matrix. Another terminal selected Node 26 against SQLite compiled for Node 24 and failed closed. Correcting that terminal's version restores readiness; switching Node requires a matching native install in the separate checkout. Keep install/build/start on the same Node version.
- **Dependency maintenance:** production audit is clean. Five existing development-only advisory entries remain in the braces/micromatch/fast-glob/Next ESLint chain; npm's proposed forced downgrade is breaking and was not applied. Deprecated lint/native-build tooling warnings remain.
- **Presenter activation:** retained PID 68163 still serves its old build. RC verification uses isolated builds/processes/DBs. Activate only with explicit approval, normal shutdown, verified matching backup and nondestructive migration. Release marker is a compiled version label, not remote cryptographic Git attestation.
- **Backup trust:** verified 0700/0600 files protect against accidental disclosure, not encryption or a hostile privileged OS actor. Copy the private database/key pair to approved secure storage as appropriate; never submit or commit it. Verification checks snapshot consistency/current signatures; deliberately altered historical evidence remains retained.

Future work: real-provider evaluations with fresh approval, visual QA, independent admin authentication/deployment isolation, broader tested adapters, stronger evidence attestation and production memory/trace backends. None is claimed as implemented by this RC.
