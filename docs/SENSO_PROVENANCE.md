# Senso and untrusted source provenance

The optional adapter implements documented POST https://apiv2.senso.ai/api/v1/org/search/context with X-API-Key and bounded `{query}` only—not an invented answer API. Configure `GHOSTOPS_SPONSOR_EGRESS=1`, `GHOSTOPS_SENSO_ENABLED=1`, private `SENSO_API_KEY`, and comma-separated approved synthetic `GHOSTOPS_SENSO_CONTENT_IDS`. Context retrieval may consume credits. No organization knowledge base, upload or genuine authenticated Senso call was accessed.

Local fixture is default in Sponsor Integrations → context. It carries synthetic document/version/chunk IDs and is explicitly local-fixture, NEVER verified Senso. Both real results and fixture preserve source IDs/versions/chunks/content hashes, reject nonapproved IDs, and classify all passage text untrusted for instruction purposes. Response limit 80 KiB / 10 passages; combined agent context <=4000 characters. Only metadata is stored in IntegrationRun; bounded synthetic text is held in a SourceDocument with verified content hash for the existing gateway.

The returned contextId is used by a granted external SDK client with read_document, resource docs/context, arguments contextId. Gateway binds the source itself and verifies trust/content hash; client metadata cannot grant policy. Protected-memory writes still deny independently. The context ID can be used in model-org after explicit provider approval. Existing explicit message references preserve originating source provenance; access alone does not establish that instructions influenced a model. Forensic packages supplement matching decision source IDs with persisted retrieval metadata, not raw passages.
